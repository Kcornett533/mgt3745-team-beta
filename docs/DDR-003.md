# DDR-003: Strict Verification Schema and Error Handling

## Status
Proposed — update to Accepted after team review.

## Context
Phase 2 requires candidate verification data to be checked before it is saved. The browser and Worker both need validation so that an invalid request cannot bypass the form and reach the database. The project also requires clear errors when required fields are missing.

## Decision
The client will validate required fields before submitting the form. The Worker will independently validate the request before any database insert. Requests with missing required fields will return HTTP 400 with the JSON error message specified in F-002. The page will display validation errors using safe DOM methods and preserve the user's entered values. Database queries will use parameterized statements.

The exact relationship between the five F-002 payload attributes and the coursework declarations required by F-001 must be confirmed with the Specifier and Architect before the schema is finalized.

## Consequences
Invalid submissions should not be stored. Users receive a clear error and can correct their form. Validation is enforced on both the client and server, but the required fields and their representation must stay consistent with the agreed specification.

## Verification
- Test requests with missing required fields.
- Confirm invalid requests return HTTP 400.
- Confirm invalid requests do not create database records.
- Test a valid request against the agreed schema.
- Confirm the page displays errors without clearing the form.
- Confirm database queries are parameterized.
