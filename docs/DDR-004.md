# DDR-004: Phase 2 build of F-01, F-02, F-03 delegated to Claude Code

## Status
Accepted by Regina Choi (Phase 2 Implementer), October 22, 2026.

## Task
Build the Must-be features from `context/FEATURES.md` on the ADR-001 stack: the Worker (`worker.js`), shared rules (`eligibility.js`), the D1 schema (`schema.sql`) and synthetic seed data (`seed.sql`), the static page (`public/`), `wrangler.toml`, and smoke tests (`test/eligibility.test.js`). Also the TOOLS.md Cloudflare row update and the README See It Work and Status sections.

## Tool and Model
Claude Code (CLI), model Claude Opus 5.5 (`claude-opus-5-5`). Note: `context/CLAUDE.md` lists Claude 3.5 Sonnet / Claude 3 Opus as approved Claude models. This is a newer Claude model from the same approved vendor, and the deviation is recorded here for the team to confirm.

## Economic Rationale
The deadline was hours away, and the `main` branch still carried the HW4 evidence-log Worker. Writing the Worker, schema, and page by hand would have taken longer than was left. Delegating drafting and keeping a human review and live verification was the only way to ship a build that can be evaluated.

## Crossing
- Into the tool: the repository contents (specs, context files, existing code). No secrets, no real personal data.
- Out of the tool: code and docs written to the working tree, committed only to feature branches and pushed for human review. The tool ran `wrangler` under Regina's own login to create the D1 database `team-beta-candidates`, apply the schema and seed, and deploy. No credentials were written to any file.
- Runtime data: synthetic candidate records only, stored in D1 under Cloudflare's terms (see `context/TOOLS.md`). No AI call happens at runtime.

## Decisions the tool made that the team must confirm
1. **Coursework field.** F-01 criterion 4 needs a completed governance course, but F-02 restricts the payload to five attributes. The build adds a sixth field, `coursework`, so F-01 can be evaluated. ADR-001 already lists "coursework declarations" as stored data. The Specifier should amend F-02 through a reviewed PR or ask for a change.
2. **Target intake year = 2027.** F-01 criterion 2 says "<= 1 year from target intake" without naming the year, so graduation years 2026 and 2027 pass.
3. **"Verified work visa"** is offered as the option `Verified Work Visa`, and `None` fails criterion 3.
4. **Static assets on the same Worker.** `public/` is served through Workers static assets, so the page and API share one origin and one URL. This still fits ADR-001 (Worker + D1, plain HTML/CSS/JS). The Architect should update the diagram if it shows GitHub Pages hosting the frontend.
